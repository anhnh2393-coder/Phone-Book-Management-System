# 2. Non-Functional Requirements

The Phone Book Management System should satisfy the following
non-functional requirements.

**NFR01 – Performance:**
The system should respond to operations such as adding, searching,
updating, and deleting contacts within 2 seconds under normal conditions.

**NFR02 – Usability:**
The system should provide a simple, clear, and user-friendly interface
that allows users to easily manage contacts.

**NFR03 – Reliability:**
The system should operate correctly and maintain data consistency
during contact management operations.

**NFR04 – Security:**
The system should protect contact information from unauthorized access
or modification.

**NFR05 – Data Integrity:**
The system should prevent invalid, incomplete, or duplicate contact
information from being stored.

**NFR06 – Maintainability:**
The system should have a clear and modular structure so that developers
can easily maintain, fix, and update the system.

**NFR07 – Scalability:**
The system should be able to handle an increasing number of contacts
without significant performance degradation.

**NFR08 – Availability:**
The system should be available whenever users need to add, search,
update, or manage contacts.

**NFR09 – Compatibility:**
The system should work correctly on the supported operating system
and common devices used by users.

**NFR10 – Backup and Recovery:**
The system should support data backup and recovery to prevent
permanent data loss.

**NFR11 – Accuracy:**
Search results and contact information displayed by the system should
be accurate and consistent with the stored data.

**NFR12 – Portability:**
The system should be designed so that it can be transferred or deployed
to another supported environment with minimal modification.
